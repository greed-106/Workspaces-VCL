# VCL 工作区平台 使用指南

本文档面向平台使用者,说明账号申请、数据卷使用、工作区创建与维护、实例的访问方式,以及数据的持久化范围。所有操作均在浏览器中完成,无需在本地安装任何客户端。

---

## 一、账号申请与初始设置

1. 向管理员申请账号,需要提供两项信息:常用邮箱(用于登录)和姓名。
2. 管理员创建账号后,会提供控制台地址和初始密码。
3. 打开控制台地址,使用邮箱与初始密码登录。
4. 首次登录后请修改初始密码:右上角头像 → **Settings** → **Security** → **Password**,依次填写 Old Password、New Password、Confirm Password 后保存。

密码建议使用 12 位以上、包含大小写字母、数字与符号的组合。若忘记密码,请联系管理员重置;当前部署未配置邮件服务,登录页的密码找回功能不可用。

## 二、数据卷

数据卷是用户的个人持久化存储,独立于工作区存在:删除工作区不会删除数据卷及其中数据。

### 2.1 申请

1. 顶部导航进入 **Volumes** 页面,填写卷名与容量后提交。
2. 容量规则:单卷 100 至 1000 GB,每位用户所有卷合计不超过 1000 GB。
3. 数据卷为个人私有,其他用户不可见,也不能挂载到他人的工作区。

### 2.2 上传文件

- 在 **Volumes** 页面选择目标卷后上传文件。
- 支持大文件分片上传与断点续传:传输中断后可继续,已完成部分不会重传。
- 遇到同名文件时,可选择覆盖原文件,或保留两份(新文件自动重命名为 `原名(1).后缀`)。
- 上传前会校验卷内剩余容量,容量不足时会拒绝并给出提示。
- 上传的文件位于卷的根目录。

### 2.3 删除

删除卷需要二次确认,并要求当前没有正在运行的工作区挂载该卷。删除后数据不可恢复,重要数据请另行备份。

### 2.4 挂载到工作区

创建工作区时在「数据卷」配置项中选择自己的卷,卷会挂载到实例内的 `/mnt/data`。同一个卷允许同时挂载到多个工作区,但多个实例并发写入同一文件会导致内容异常,需要使用者自行避免。

## 三、创建与修改工作区

### 3.1 创建

1. 顶部导航进入 **Workspaces**,选择 **Create Workspace**。
2. 选择模板(当前提供 `kubernetes`)。
3. 依次选择配置项后创建。页面顶部的容量条显示集群剩余资源,资源不足时会拒绝创建并说明原因。
4. 创建过程约 1 至 2 分钟,状态变为 Running 后即可使用。

### 3.2 配置项说明

| 配置项 | 可选范围 | 后续是否可修改 |
| --- | --- | --- |
| CPU | 8 / 16 / 32 核 | 可修改 |
| 内存 | 16 / 32 / 48 GB | 可修改 |
| GPU 型号 | 不使用显卡 / NVIDIA RTX 3080 Ti | 可修改 |
| GPU 张数 | 1 至 4 张 | 可修改 |
| 开发镜像 | Ubuntu 24.04(默认)、Ubuntu 24.04 + CUDA 12.8 | 不可修改 |
| 磁盘大小 | 100 至 500 GB | 不可修改 |
| 数据卷 | 选择自己的卷,或留空不挂载 | 可修改 |

需要 GPU 的工作区建议选择 CUDA 版镜像。

### 3.3 修改配置

**可修改的配置项**(CPU、内存、GPU 型号与张数、数据卷):进入该工作区页面 → **Parameters** → 修改后保存。工作区会自动重建并重启,耗时约 1 分钟,`/home/coder` 与数据卷中的数据不受影响。

**不可修改的配置项**(开发镜像、磁盘大小):需要新建工作区。建议先将需要保留的数据上传到数据卷,再在新工作区中挂载同一个卷,确认无误后删除旧工作区。

## 四、访问实例的方式

平台提供两种访问方式,均在浏览器中完成,推荐使用这两种方式,无需在本地安装客户端或命令行工具。

### 4.1 Web 端 VS Code

- **入口**:工作区页面 → **Apps** → **VS Code**
- **说明**:浏览器中完整的 VS Code,支持扩展安装、文件编辑与集成终端;首次打开需要数秒加载。
- **适用**:代码开发、调试,以及需要图形化编辑器的场景。
- 安装的扩展与个人设置保存在 `/home/coder`,停止或重启工作区后仍然保留。

### 4.2 Terminal(网页终端)

- **入口**:工作区页面 → **Terminal**
- **说明**:浏览器中的终端,登录后即为 `coder` 用户,可直接执行命令。
- **适用**:安装依赖、编译、运行训练脚本、查看资源使用情况。
- VS Code 的集成终端与 Terminal 等价,可任选其一。

### 4.3 容器内的用户与权限

实例内统一使用 `coder` 用户(uid 1000),并已配置**免密 sudo** 权限,可以安装系统软件包、修改系统配置,行为与常规 Linux 环境一致。

## 五、数据的持久化范围

| 位置 | 停止 / 启动工作区后 | 删除工作区后 |
| --- | --- | --- |
| `/home/coder`(代码、配置、用户目录下安装的软件) | 保留 | 清空 |
| `/usr/local`、`/etc`、`/opt`、`/var/lib`、`/var/cache`(通过 sudo 安装的软件、修改过的系统配置) | 保留 | 清空 |
| `/mnt/data`(需先申请数据卷,并在创建或修改工作区时选中) | 保留 | 保留 |
| `/tmp`、`/var/tmp`(内存盘,容量 8 GB) | 清空 | 清空 |
| 其他位置(`/root`、`/var/log` 等未列出的路径) | 清空 | 清空 |

注意事项:

- 需要长期保存的数据请放在 `/home/coder` 或数据卷 `/mnt/data`。
- `/tmp` 仅用于临时文件,重启后清空;该目录占用内存配额,写入过多会影响实例性能。
- 未申请数据卷时,`/mnt/data` 是全体用户共享的 1 GB 占位空间,请勿在此存放数据;申请并挂载自己的卷后,`/mnt/data` 才对应个人存储。
- 停止(Stop)工作区不会丢失数据,长期不用时可停止以释放资源;删除(Delete)工作区会清空系统盘,数据卷不受影响。

## 六、确认实例的实际配置

资源限制在容器外部(内核层)实施,因此部分常用工具显示的是宿主机配置,而非实例配额:

- `free -h`、`lscpu`、`cat /proc/cpuinfo` 显示的是宿主机(48 核、377 GB),**不是实例配额**。

在 Terminal 中执行以下命令可获取准确值:

| 查询项 | 命令 | 说明 |
| --- | --- | --- |
| CPU 核数 | `cat /sys/fs/cgroup/cpu.max` | 例如 `800000 100000`,第一个数除以第二个数为核数(此处为 8 核) |
| 内存上限 | `cat /sys/fs/cgroup/memory.max` | 单位为字节,`17179869184` 即 16 GiB |
| 磁盘容量 | `df -h /home/coder` | 显示实际配额,与申请值一致 |
| GPU 张数 | `nvidia-smi -L` | 仅列出分配给该实例的 GPU |

实例内自带 `coder` 命令,可直接读取同类信息:

```bash
coder stat cpu
coder stat mem
coder stat disk
```

超出配额时的表现属于正常保护机制:CPU 会被限速,内存超出上限时进程会被终止,磁盘写满时写入会直接失败。

## 七、常见问题

| 问题 | 处理方式 |
| --- | --- |
| Web 端 VS Code 打不开 | 确认工作区状态为 Running,刷新页面后重试;仍无法打开请联系管理员 |
| 工作区长时间停留在 Starting | 可能为节点资源紧张(参见申请页容量条)或镜像拉取较慢;超过 5 分钟请联系管理员 |
| 磁盘空间不足 | 清理 `/home/coder` 中的缓存与不再使用的环境;冷数据请移至数据卷 |
| 忘记密码 | 联系管理员重置 |
| 需要更多 CPU / 内存 / GPU | 在工作区 Parameters 中调整(需集群存在余量);若无法调整,说明当前资源不足,可联系管理员协调 |
| 需要长期保存的大文件 | 先上传至数据卷,再在工作区中通过 `/mnt/data` 使用 |
