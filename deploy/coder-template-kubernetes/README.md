# VCL 工作区模板

本模板提供容器化开发实例:CPU、内存、GPU 与磁盘均按申请值做硬性限制,通过浏览器访问 Web 端 VS Code 或网页终端。

## 实例规格

- **计算资源**:CPU 8 / 16 / 32 核,内存 16 / 32 / 48 GB,GPU 可选 1 至 4 张 NVIDIA RTX 3080 Ti,也可不使用显卡。
- **系统盘**:100 至 500 GB,为硬配额,实例内 `df` 显示的容量即为申请值。
- **镜像**:Ubuntu 24.04(默认)或 Ubuntu 24.04 + CUDA 12.8,需要 GPU 时建议选择 CUDA 版。
- **访问方式**:Web 端 VS Code(工作区页面 → Apps → VS Code)与网页终端(工作区页面 → Terminal),均在浏览器中完成,无需安装客户端。
- **用户身份**:实例内统一为 `coder` 用户(uid 1000),已配置免密 `sudo`。

## 创建与使用

1. 进入 **Workspaces** → **Create Workspace**,选择本模板,依次选择配置项后创建。
2. 页面顶部的容量条显示集群剩余资源(每 10 秒自动刷新,也可手动刷新)。提交时会再次校验,资源不足将拒绝创建并说明原因。
3. 创建过程约 1 至 2 分钟,状态变为 Running 后即可通过 Web 端 VS Code 或网页终端使用。
4. 需要调整配置时,进入工作区页面修改 **Parameters**。工作区会自动重建并重启,耗时约 1 分钟,`/home/coder` 与数据卷中的数据不受影响。
5. 停止、启动工作区均保留数据;删除工作区会清空系统盘与 `/home/coder`,已申请的数据卷不受影响。

## 数据卷

- 在 **Volumes** 页面申请,单卷 100 至 1000 GB,每位用户合计不超过 1000 GB。
- 创建或修改工作区时选择自己的卷,实例内固定挂载到 `/mnt/data`。
- 支持分片上传与断点续传,遇同名文件可选择覆盖或保留两份,上传前会校验卷内剩余容量。
- 同一个卷可同时挂载到多个工作区,并发写入同一文件会导致内容异常,需自行避免;删除卷要求没有运行中的工作区挂载它,并需二次确认。
- 数据卷独立于工作区存在,删除工作区不会删除卷及其数据。

## 使用建议

- 集群为单节点、1GbE 网络、无 InfiniBand,适合单机多卡场景;工作区之间网络互通。
- 数据盘由 4 块磁盘线性拼接,无冗余,仅适合存放冷数据,不可作为备份使用。
- `/tmp` 与 `/var/tmp` 为内存盘,重启后清空;需要保留的数据请放在 `/home/coder` 或数据卷中。
- 大文件建议先上传至数据卷,再在实例中通过 `/mnt/data` 使用。

更完整的说明(账号申请、密码修改、数据持久化范围、如何确认实例的实际配置)见管理员发布的《VCL 工作区平台 使用指南》。
