# VCL 工作区平台 使用指南

这份文档写给使用平台的同学,讲清楚怎么申请、怎么用、数据放在哪里、哪些配置能改。不需要任何容器或 Kubernetes 基础,照着做就行。

---

## 一、先找管理员开账号

1. 联系管理员,提供两样东西:一个**常用邮箱**(用来登录)、你希望显示的名字。
2. 管理员创建好之后,会把这个地址和初始密码发给你:控制台地址(例如 `http://10.129.164.15:3001`)。
3. 打开地址,用**邮箱 + 初始密码**登录。

### 登录后请先改密码

不要一直用管理员给的初始密码,建议登录后立刻换成自己的强密码:

**右上角头像 → Settings → Security → Password**,依次填「Old Password(初始密码)」「New Password(新密码)」「Confirm Password(再输一遍)」,保存即可。

新密码建议 12 位以上,大小写字母、数字、符号混合。忘记密码时目前只能找管理员重设(这套部署没有配邮件服务,登录页的「忘记密码」收不到验证码)。

## 二、申请一块属于自己的数据卷(推荐先做)

数据卷是你自己的大容量存储,和工作区是**分开的**:工作区删掉,卷和卷里的数据都还在。

1. 顶部导航 `Volumes` → 填**卷名**(比如 `dataset`)和**容量** → 申请。
2. 容量规则:单卷 100 到 1000 GB,每人所有卷加起来不超过 1000 GB。
3. 卷是你的私有空间,别人看不到,也不能挂到别人的工作区上。

### 往卷里放文件

在 `Volumes` 页面选中你的卷,选择文件上传即可。几个特点:

- **支持大文件与断点续传**:中途网络断了、页面关了,重新打开继续传,已经传过的部分不会重传。
- **同名文件会问你**:是覆盖原来的,还是保留两份(自动改名成 `名字(1).后缀`)。
- **上传前会检查剩余空间**:卷里放不下会直接提示,不会白传。
- 上传的文件都落在卷的根目录下。

### 关于删除

删除卷需要二次确认,而且要求**没有正在运行的工作区在用它**。删掉之后里面的数据不可恢复,重要数据请另外备份。

## 三、创建自己的工作区(实例)

1. 顶部导航 `Workspaces` → `Create Workspace`。
2. 选模板(目前只有一个:`kubernetes`)。
3. 依次选配置,然后 Create。申请页顶部的**容量条**会显示集群现在还剩多少资源,数字不够时会给出提示或直接拒绝,并说明原因。
4. 创建大概需要 1 到 2 分钟,状态变成 Running 就可以用了。

### 配置选项,以及以后能不能改

| 配置 | 可选范围 | 之后能否修改 |
| --- | --- | --- |
| CPU | 8 / 16 / 32 核 | 可以改 |
| 内存 | 16 / 32 / 48 GB | 可以改 |
| GPU 型号 | 不使用显卡 / NVIDIA RTX 3080 Ti | 可以改 |
| GPU 张数 | 1 到 4 张 | 可以改 |
| 开发镜像 | Ubuntu 24.04(默认)、Ubuntu 24.04 + CUDA 12.8 | **不能改** |
| 磁盘大小 | 100 到 500 GB | **不能改** |
| 数据卷 | 选自己的卷,或留空不挂载 | 可以改 |

**怎么改可以改的配置**:进入这个工作区的页面 → `Parameters` → 改完保存,工作区会自动重建并重启,大约 1 分钟。重启不影响 `/home/coder` 和数据卷里的数据。

**不能改的配置怎么办**:

- 想换镜像(Ubuntu 换 CUDA 版)、想把磁盘改大:**只能新建一个工作区**,把旧工作区里需要的数据先放到数据卷,再在新工作区里挂上同一个卷;或者先复制到数据卷再删除旧工作区。
- GPU 工作区建议选 CUDA 版镜像;先建错了也不用慌,把数据搬到数据卷后重建一个即可。

## 四、在工作区里干活

- **浏览器版 VS Code**:工作区页面 → `Apps` → `VS Code`,直接在浏览器里打开,不需要安装任何客户端。第一次打开会慢几秒。
- **终端**:工作区页面 → `Terminal`,或者本地用 `coder ssh <工作区名>`(需要装 CLI,工作区页面有安装命令)。
- **容器里的用户**:统一是 `coder`,有免密的 `sudo` 权限。用 `sudo apt install ...` 装系统软件、改系统配置都没问题。
- 想临时装 VS Code 插件、改主题等,直接在浏览器版 VS Code 里操作,配置会跟着 `/home/coder` 保留。

## 五、数据放在哪里才能留住(很重要)

| 位置 | 停止/启动工作区后 | 删除工作区后 |
| --- | --- | --- |
| `/home/coder`(你的代码、配置、用户目录下装的软件) | **保留** | 清空 |
| `/usr/local`、`/etc`、`/opt`、`/var/lib`、`/var/cache`(用 `sudo apt` 装的软件、改过的系统配置) | **保留** | 清空 |
| `/mnt/data`(需要先在 Volumes 里申请卷,并在创建/修改工作区时选上它) | **保留** | **保留** |
| `/tmp`、`/var/tmp`(内存盘,容量 8 GB) | 清空 | 清空 |
| 其它位置(`/root`、`/var/log` 以及随手写在系统目录里的文件) | 清空 | 清空 |

几个要点:

- 想长期保存的东西,放 **`/home/coder`** 或 **数据卷 `/mnt/data`**。
- `/tmp` 只放临时文件,重启就没了;而且它占的是内存额度,塞太多会拖慢甚至把进程杀掉。
- **没有申请数据卷时,`/mnt/data` 是一个所有人共用的 1 GB 占位空间,不要往里放东西**;申请了自己的卷并在工作区里选上之后,`/mnt/data` 才是你的卷。
- 同一个数据卷可以同时挂到多个工作区(比如把同一份数据集给多个实例用),但如果两个实例同时写同一个文件,内容会乱,需要你自己避免。
- 停止工作区(Stop)不花钱也不丢数据,长时间不用可以停掉;删除(Delete)会清空系统盘,数据卷不受影响。

## 六、怎么正确查看自己实例的配置

因为限制是在容器**外面**(内核层面)做的,有些常见命令会显示整台服务器的配置,而不是你的额度:

- `free -h`、`lscpu`、`cat /proc/cpuinfo` → 显示的是宿主机:48 核、377 GB 内存,**不是你的额度**。
- 下面这些才是你真正拿到的:

| 想看什么 | 命令 | 怎么看 |
| --- | --- | --- |
| CPU 核数 | `cat /sys/fs/cgroup/cpu.max` | 例如 `800000 100000`,用第一个数除以第二个数 = 8 核 |
| 内存上限 | `cat /sys/fs/cgroup/memory.max` | 单位是字节,`17179869184` = 16 GiB |
| 磁盘容量 | `df -h /home/coder` | 直接显示你的配额,申请多少就是多少 |
| GPU 张数 | `nvidia-smi -L` | 只列出分配给这个工作区的卡 |

更省事的办法:容器里自带 `coder` 命令,可以直接读准:

```bash
coder stat cpu    # 例如 0.03/8 cores (0%)
coder stat mem
coder stat disk
```

如果发现某个工具报的数字和申请的不一致,以 cgroup 文件(`cpu.max`、`memory.max`)和 `df` 为准。超过额度时,CPU 会被限速、内存超了进程会被杀、磁盘写满会直接报错,这些都是正常的保护机制。

## 七、常见问题

- **网页 VS Code 打不开**:先确认工作区状态是 Running,刷新页面再试;仍不行找管理员。
- **一直卡在 Starting**:可能是节点资源紧张(看申请页的容量条)或镜像在拉取;超过 5 分钟找管理员。
- **磁盘满了**:先清理 `/home/coder` 里的缓存和用不到的环境;冷数据请放到数据卷。
- **忘记密码**:找管理员重设。
- **想扩容 CPU/内存/GPU**:在工作区 `Parameters` 里改(需要集群还有余量);改不了说明当前资源不够,可以找管理员协调。
- **需要长期保存的大文件**:先上传到数据卷,再在工作区里从 `/mnt/data` 使用。
